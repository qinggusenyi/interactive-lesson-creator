# 从场景到可环视课件

主要参考是用户指定的百草园**分享环视版**，不是旧 index.html 的平移版。固定机位环视采用 WebGL，素材与热点方位共同决定体验。图片再漂亮，投影/接缝/热点没校准也不能算完成。

## 1. 按教学任务确定方位内容

先列 `场景 → 观察对象 → 原文依据 → 学生动作`。对象分布在不同方位，给环视一个理由；不把所有热点挤在正前方。初始视角至少看见一个有效目标，并有同内容文字入口可跳转到其他方位。

## 2. 制作 2:1 全景素材

优先经专业流程输出的等距柱状图。用可用图像生成工具时，提示词明确：

> 完整球面等距柱状纹理，水平360°、垂直180°，2:1画幅；同一固定机位，地平线约在图高50%；左右边缘物体/光照衔接，天顶地底适合球面映射；按所需方位安排可辨认的大物件；无文字、UI、水印。文学情境插画，不是历史原貌。

把具体课文的地貌、季节、物件和画风补进去。不要把普通16:9图拉伸到2:1。推荐正式资源4096×2048，先用较小图验证。当前例子由本次新生成1774×887样片转JPEG，不能充当专业无缝/严格投影的证明，极区和边界需人工继续审看。

## 3. 校准热点

以图像左上为原点，物件中心百分比为 x/y。先换算初值：

`yaw = (x/100 - 0.5) × 360`

`pitch = (0.5 - y/100) × 180`

再在真实查看器中拖动、抬头、缩放校准。坐标记录在 lesson.json 的 yaw/pitch。例如图像中线正中对应0°/0°，右边界接近180°。模板的纹理映射和热点用同一相机模型，不能混用 plane 百分比坐标。

## 4. 镜头与热点同步

原生 WebGL shader 把每个屏幕像素的视线方向投到全景纹理；DOM 热点把世界方向用相机**逆旋转**投影回屏幕，背面和画外点隐藏。点击列表/热点后用短 smoothstep 转向；拖动会取消旧转向。滚轮调 FOV，yaw跨±180°连续，pitch限幅，重置回初始方位。

## 5. 环视专项验收

- 实际拖动时是改变观察方向，不是整张图片在容器里左右移动。
- 从179°跨到−179°没有控制卡住；这只能证明相机连续，不能证明图像接缝无痕。
- 物件从画面中心移动到边缘时，热点应跟着；抬头后也应贴合。
- 检查纹理是否上下颠倒、地平线/物件是否过度拉伸、边缘是否重复。
- 无WebGL时明确显示静态阅读降级。教材文本、提问和解读仍能用。
- 单独复制index.html离线打开，场景图片仍正常；不能用网络贴图或本地文件夹遮掩缺资源。
